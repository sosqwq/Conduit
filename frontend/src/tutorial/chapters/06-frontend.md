# 06 前端骨架与鉴权

## 本章做了什么

第一次打开设置页时，浏览器需要回答两个问题：这个地址要显示哪个 React 组件？当前登录的是谁？前一个问题由路由解决，后一个要结合本地令牌与服务器的确认。本章跟踪一次登录、刷新和退出，再跟踪你正在阅读的教程。教程目录和章节都允许匿名访问。

| 地址 | 读者可执行的操作 | 访问的数据 |
| --- | --- | --- |
| `/register`、`/login` | 注册新账号、用邮箱和密码登录 | 后端用户接口 |
| `/settings` | 修改自己的资料或密码、退出登录 | 当前登录用户及其令牌 |
| `/tutorial` | 按后端、前端、工程浏览章节 | 随前端构建的章节索引 |
| `/tutorial/06` | 阅读本章，在侧栏或页末切换章节 | 随前端构建的 Markdown 正文 |

## 用到的技术

- **Vite 和 TypeScript。** Vite 在开发时把模块提供给浏览器，生产构建时整理源码、样式与依赖。TypeScript 在构建前检查值和函数的类型关系。浏览器最终运行 JavaScript；类型定义帮助开发者及早发现调用错误，服务器返回的数据仍需运行时处理。
- **组件与 Hooks。** React 组件是根据输入和状态返回界面描述的函数，JSX 让代码可以写成接近 HTML 的结构。`useState` 记住会改变呈现的值；更新它会触发新一轮渲染。`useRef` 保存跨渲染的引用，比如当前请求的取消控制器，改变引用本身不触发渲染。`useEffect` 把订阅、网络恢复或清理等外部工作放在渲染之外。若手工操作 DOM，需要自己维护这些状态与元素之间的一致性。
- **React Router。** 单页应用先载入一份 HTML，随后由前端路由把路径与组件对应起来。`Link` 在同一个应用内改变地址，`useParams` 读取动态路径，`useNavigate` 在保存成功等时机改变页面。若每次切换章节都刷新整个站点，就要重新初始化应用状态。
- **Context 与浏览器存储。** Context 让下层组件读取共享的登录状态，无须把令牌穿过每一层组件参数。React 状态随刷新消失，`localStorage` 则在同一来源下跨刷新保留值。本项目按 RealWorld 用例将令牌保存到 `jwtToken`，加载账号详情时仍向后端验证。
- **Markdown 渲染。** Markdown 用普通文本表达标题、列表、代码等；react-markdown 将解析结果渲染为 React 元素，remark-gfm 支持教材里的表格。highlight.js 对标有语言的代码块进行语法高亮。若只把整个文件塞进一个文本框，目录结构、表格和代码的语法层次都无法呈现。

## 代码走读

**从输入框到 HTTP。** 在登录页提交表单时，表单事件处理器阻止浏览器按默认方式整页导航，从表单读取邮箱和密码，并包装为 `user` 对象。它创建 AbortController、标记请求进行中，再发 POST。登录和注册提交公开凭据，设置页提交修改时才携带原有令牌。下面的 API 客户端负责拼接同源地址、序列化 JSON，以及使用后端要求的 Token 认证头。

来源：`frontend/src/lib/api.ts`

```typescript
  const headers: Record<string, string> = { Accept: 'application/json' }
  if (options.token) headers.Authorization = `Token ${options.token}`
  if (options.body !== undefined) headers['Content-Type'] = 'application/json'
  const response = await fetch(`/api${path}`, {
    method: options.method ?? 'GET', headers, signal: options.signal,
    body: options.body === undefined ? undefined : JSON.stringify(options.body),
  })
```

`fetch` 收到 401、409 等 HTTP 错误时仍会返回响应。客户端检查 `response.ok`，把后端提供的逐字段错误解析为 `ApiError`。表单将错误显示在页面中。登录成功后，`SessionProvider` 的 `accept` 把新令牌保存到浏览器，清除查询缓存，并将用户与令牌放入 React 状态；接着页面导航回首页。设置页只发送相对原值发生变化的字段，例如清空简介会提交 `null`，不会把空密码输入框当成一次改密请求。

**刷新后确认“我是谁”。** 留意初始渲染的三种可能：没令牌时可以立即渲染游客状态；有令牌时先呈现加载状态；当前账号详情必须等服务器返回。这里的 `useState` 接收初始化函数，在读取本地令牌后产生第一份状态快照。

来源：`frontend/src/auth/session.tsx`

```typescript
  const [session, setSession] = useState<Snapshot>(() => {
    const token = localStorage.getItem(tokenKey)
    return token ? { status: 'loading', token, user: null } : guest
  })
```

挂载后的恢复函数用令牌请求 `GET /api/user`。有效结果进入 authenticated；明确的客户端错误会退出登录并清除令牌；网络或服务端故障进入 unavailable，保留令牌以支持重试。恢复过程中如果用户已经退出、账号在其他标签页变化或组件卸载，取消信号可阻止旧响应把登录状态重新写回。退出还清除查询缓存，以免同一个浏览器切到另一个账号后短暂显示前一个人的个性化结果。

**从教程地址到 Markdown。** 看看本章来自哪里。Vite 在构建时展开匹配的文件，`?raw` 要求以文本导入，`eager` 让索引立即取得这些文本。模块用文件名前缀与一级标题核对两位章节编号，合并所在组别和简介，最后按编号排序。比如文件标题文字以后可以修订，`/tutorial/06` 仍然指向同一章。

来源：`frontend/src/tutorial/catalog.ts`

```typescript
const sources = import.meta.glob<string>('./chapters/*.md', {
  eager: true,
  query: '?raw',
  import: 'default',
})
```

访问目录时按三个组别展示数组中的章节。访问 `/tutorial/06` 时，路由把 `06` 交给 `TutorialChapter`。该组件用同一个数组选定正文和前后相邻章，侧栏当前链接带上 `aria-current="page"`，屏幕阅读器也能知道所在位置。找不到某个编号时会展示返回目录的入口。正文渲染过程中，来源行保留真实文件路径，围栏内的代码按其语言单独渲染。

来源：`frontend/src/tutorial/Tutorial.tsx`

```tsx
          <Markdown remarkPlugins={[remarkGfm]} components={{ code: TutorialCode, p: Paragraph }}>
            {current.markdown}
          </Markdown>
```

**验证界面表现。** Vitest 运行测试，React Testing Library 从读者能感知的角色和名称查找元素。教程测试给内存路由一个初始地址，实际点击“下一章”，检查一级标题、侧栏当前状态和返回链接；另外还检查表头、来源路径和高亮标记。与只断言模块能被导入相比，这可以发现按钮留在原页、表格退化成普通文本等问题。

## 设计取舍

为什么刷新时不从存储中读取一份永久用户资料？用户名、头像乃至令牌有效性都可能在另一处变化。保留令牌，让服务器返回权威的当前用户需要一次请求，却能把资料和权限与数据库重新对齐。恢复尚未结束、凭证已失效与网络暂时不可用是不同状态；如果一遇到网络波动就清空令牌，短暂故障会意外使用户退出。

教程内容随源码构建。这样可以用同一提交追踪实现和讲解，在没有登录态和文章数据库时也能阅读。代价是改一行教材也要发布前端，初次下载包含已打包的章节文本。目录、侧栏与相邻页共享同一个有序数组，可避免增加新章时出现“能在目录找到却不能从上一章跳到”的问题。

## 常见错误

| 现象 | 排查方法 |
| --- | --- |
| 登录成功但刷新后回到登录页 | 查看本来源下是否有 `jwtToken`，随后检查 `GET /api/user` 的状态码与头部；不要在日志或讨论帖里复制真实令牌。 |
| 登录接口报错，界面却直接导航 | 检查客户端是否验证 `response.ok`，以及导航是否只在 `accept` 成功后发生。 |
| 点击提交后接口收到两次相同写入 | 对照表单的进行中标志、按钮禁用状态和请求引用；确认请求结束时才允许下一次提交。 |
| 手工把教程标题改好，网页仍显示旧版本 | 检查改动是否位于 `src/tutorial/chapters`，文件是否被当前构建打包；已部署的静态页面需要包含新构建。 |
| 教程能显示代码，却没有语法颜色 | 确认围栏使用了受支持的语言标记，代码元素内有高亮标签，页面也加载了相应样式。没有语言的行内命令应保持普通代码格式。 |

## 自测与练习

1. 为什么把用户对象放在 `useState` 后，刷新还需要读取 `localStorage` 并请求后端？
2. 登录接口返回 401，为什么只写 `try/catch(fetch(...))` 不够？
3. 退出登录时还有一个恢复请求在运行，如果稍后才返回成功，怎样避免重新显示旧账户？
4. 教程从第 05 章跳到第 06 章时，需要向后端请求哪一个教程接口？章节顺序来自哪里？
5. 测试已经断言代码块存在，为什么还要确认其中的高亮标记和表格的列标题？

**动手练习。** 在本地注册并登录，打开浏览器网络面板，刷新设置页，寻找读取当前账号的请求。随后退出，打开 `/tutorial/06` 并通过侧栏切到第 02 章，再从相邻章节返回；观察章节切换是否访问文章 API，以及页面标题、地址和当前侧栏项如何对应。最后访问 `/tutorial/unknown`，从页面提供的入口回到目录。

### 参考答案

1. React 状态只属于当前加载的应用实例，刷新后会重建。本地令牌能跨刷新保存，但当前账号资料及令牌有效性仍由后端确认。
2. 有 HTTP 响应时，fetch 对 4xx/5xx 通常正常完成 Promise；显式检查响应状态，才能让错误处理和表单展示走到正确分支。
3. 退出时中止恢复请求，并在任何异步结果写入前检查取消状态。这样旧请求的结果不会覆盖较新的访客状态。
4. 阅读和切章无需教程 API。正文是 Vite 导入的本地 Markdown，顺序由核对过的两位编号决定。
5. 普通文本也能放进代码块或画出像表格的字符。检查高亮元素与真实的表头，可以确认页面完成了语法处理，也保留了读者和辅助技术依赖的结构。

练习预期：刷新设置时会出现一次带当前令牌获取用户的流程；退出后教程仍能阅读。切换章节改变路径、标题和侧栏活动项，无需读取文章数据。无效编号页给出返回目录链接。
